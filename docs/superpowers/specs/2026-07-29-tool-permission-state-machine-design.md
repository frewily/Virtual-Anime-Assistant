# 工具权限与确认状态机设计

> 状态：继承已批准的《可扩展虚拟助手架构设计》，并按用户授权后台推进
>
> 日期：2026-07-29
>
> 适用范围：工具注册、风险判定、确认、执行、取消、超时、审计与 Electron 确认界面

## 1. 背景

项目已经具备统一消息、对话编排、大模型网关、SQLite 会话与记忆，以及 Live2D 桌面运行时。下一阶段需要建立工具执行安全边界，使后续电脑控制、QQ 发送和模型 Tool Calling 都只能通过同一条受控链路执行。

本阶段不接入任意 Shell、鼠标键盘控制、文件删除或 QQ 发送。它只实现稳定的工具框架、一个无副作用的时间查询工具，以及可由测试替身验证的高风险确认流程。

## 2. 已确定的约束

1. 风险等级由本地注册表和策略计算，调用方不能提交或覆盖风险等级。
2. 低风险工具在参数校验通过后自动执行。
3. 高风险工具先创建确认请求，未经当前请求的明确批准不得执行。
4. 高风险请求默认在 60 秒后过期，并按拒绝处理。
5. 每个工具必须声明参数模型、风险等级、超时、是否支持安全取消、影响说明和敏感字段。
6. 工具参数只接受注册工具的 Pydantic 模型，不允许临时命令或任意可执行文本。
7. SQLite 只保存脱敏参数摘要，不保存密码、Token、Cookie 或完整敏感字段。
8. 当前批准只对单个请求有效，不实现“始终允许”或持久授权。
9. Electron 只负责展示和回传决定，不能自行改变风险等级或伪造执行结果。
10. 模型 Tool Calling 与真实电脑控制在后续阶段接入，不反向修改本阶段的安全边界。

## 3. 方案选择

### 3.1 采用方案

采用“纯领域模型 + 应用服务 + SQLite 仓储 + Electron 适配器”：

- `domain/tools.py` 定义不可变请求、状态、确认、结果和审计模型。
- `tools/registry.py` 保存代码内批准的工具定义。
- `tools/policy.py` 根据注册定义计算风险，并生成脱敏参数摘要。
- `tools/service.py` 负责状态转换、超时、取消和执行。
- `SqliteStore` 通过第 2 版迁移持久化请求、确认和审计事件。
- FastAPI 暴露本机工具请求、确认决定、取消和待确认列表。
- Electron 通过 WebSocket 接收确认事件，并通过 HTTP 回传批准或拒绝。

该方案让风险规则、业务状态和 UI 相互独立。未来增加 QQ 或操作系统工具时，只需实现新的注册工具和渠道适配器。

### 3.2 未采用方案

**仅使用内存状态：** 实现简单，但重启后无法审计请求和决定，不满足既定架构要求。

**由数据库触发器维护全部状态：** 原子性强，但业务规则会分散在 SQL 和 Python 中，测试和后续扩展成本较高。

**直接在 Electron 执行工具：** 会绕过后端策略和统一审计，也无法复用于 QQ 与模型调用，因此不采用。

## 4. 领域模型

### 4.1 风险与状态

风险等级：

- `low`：明确只读、无外部副作用，可以自动执行。
- `high`：可能改变系统或外部状态，必须逐次确认。

请求状态：

```text
created
├── low ──> running ──> succeeded / failed / cancelled
└── high ─> pending_confirmation
             ├── approve ─> running ─> succeeded / failed / cancelled
             ├── reject  ─> rejected
             ├── timeout ─> expired
             └── cancel  ─> cancelled
```

终态不能再次转换。重复提交相同决定返回当前状态，不重复执行工具。

### 4.2 工具定义

每个 `ToolDefinition` 包含：

- 稳定名称和用户可读标题。
- Pydantic 参数模型。
- 本地风险等级。
- 预期副作用说明。
- 执行超时秒数。
- 是否支持安全取消。
- 需要在参数摘要中遮蔽的字段名。
- 异步执行函数。

注册表拒绝空名称、重复名称和未声明处理函数的定义。API 只能访问注册表中的工具。

### 4.3 参数处理

请求参数先交给工具自己的 Pydantic 模型校验。策略层随后生成用于确认 UI 和审计的摘要：

- 敏感键统一替换为 `"[REDACTED]"`。
- 字符串限制为 200 个字符。
- 列表和字典限制深度与数量。
- 不在日志中记录原始参数或 Pydantic 校验输入。

高风险工具的完整参数只在当前进程内保留到请求终止。应用重启后，未完成请求不能恢复执行，批准时返回安全失败，避免为了恢复能力持久化敏感参数。

## 5. 应用服务

### 5.1 请求工具

`ToolExecutionService.request()` 执行：

1. 解析注册工具。
2. 使用工具参数模型校验参数。
3. 由本地策略读取风险等级并生成摘要。
4. 保存请求和 `requested` 审计事件。
5. 低风险请求进入 `running` 并立即执行。
6. 高风险请求进入 `pending_confirmation`，保存确认记录并发布桌面事件。

调用方提交未知工具或非法参数时，服务返回稳定错误，不创建可执行请求。

### 5.2 处理确认

`ToolExecutionService.decide()` 只接受 `approve` 或 `reject`：

- 先在 SQLite 事务中检查确认仍为 `pending`。
- 已过期请求原子转换为 `expired`，不执行工具。
- 拒绝原子转换为 `rejected`。
- 批准原子认领执行权并转换为 `running`。
- 只有成功认领执行权的调用才能执行工具。

并发批准、重复点击或网络重试不会造成重复执行。

### 5.3 执行、超时与取消

执行使用 `asyncio.timeout()`。成功保存结构化结果；异常只保存稳定错误码和异常类型，不保存异常文本。

服务维护当前进程内的运行任务：

- 可取消工具收到取消请求时调用 `Task.cancel()`。
- 不可安全取消的运行中工具返回冲突状态，UI 显示不能中止。
- 待确认请求始终可以取消。
- 超时转换为 `failed`，错误码为 `execution_timeout`。
- `CancelledError` 转换为 `cancelled`，并继续传播任务取消语义所需的清理。

## 6. 持久化与审计

SQLite 第 2 版迁移增加：

- `tool_requests`：请求标识、关联标识、来源、工具、风险、状态、脱敏参数摘要、超时、可取消标记、结果摘要、错误码和时间。
- `tool_confirmations`：确认标识、请求标识、状态、过期时间和决定时间。
- `tool_audit_events`：事件标识、请求标识、事件类型、脱敏详情和时间。

关键索引：

- 请求按 `correlation_id` 查询。
- 请求按状态和创建时间查询。
- 确认按状态和过期时间查询。
- 审计按请求和创建时间查询。

创建高风险请求与确认记录在同一事务中完成。确认决定与请求状态转换也在同一事务中完成。

审计事件至少覆盖：

- `requested`
- `confirmation_required`
- `approved`
- `rejected`
- `expired`
- `execution_started`
- `succeeded`
- `failed`
- `cancelled`

## 7. 本机 API 与事件

FastAPI 增加：

- `POST /api/tools/requests`：提交已注册工具请求。
- `GET /api/tools/confirmations`：列出仍待决定的本机确认。
- `POST /api/tools/confirmations/{id}/decision`：批准或拒绝。
- `POST /api/tools/requests/{id}/cancel`：取消待确认或可取消的运行请求。
- `GET /api/tools/requests/{id}`：读取安全状态和结果。

API 输入中的来源固定为 `desktop`，不能代表 QQ 或模型身份。后续适配器直接调用应用服务，并传入自身受信任来源。

工具事件通过现有 `/ws/avatar` 连接发送：

```json
{
  "type": "tool_confirmation_required",
  "confirmation": {
    "id": "confirmation-id",
    "requestId": "request-id",
    "tool": "system.example",
    "title": "示例操作",
    "arguments": {
      "target": "example"
    },
    "impact": "将改变示例目标",
    "cancellable": true,
    "expiresAt": "2026-07-29T00:00:00+00:00"
  }
}
```

WebSocket 仅负责通知。Electron 重连后通过待确认列表补齐可能遗漏的事件。

## 8. Electron 确认界面

确认卡片覆盖在 Live2D 窗口底部，展示：

- 工具标题和稳定名称。
- 脱敏后的关键参数。
- 预期副作用。
- 是否可安全取消。
- 过期时间。
- 「允许一次」和「拒绝」按钮。

界面规则：

- 所有内容使用 `textContent` 写入，不插入远端 HTML。
- 多个确认按先进先出排队。
- 按钮提交后立即禁用，避免重复点击。
- 服务端状态是唯一真相；HTTP 失败时恢复按钮并显示安全错误。
- 决定完成或请求过期后移除当前卡片并展示下一个。
- 确认卡片区域设置 `-webkit-app-region: no-drag`，避免按钮被窗口拖动吞掉。

## 9. 内置低风险工具

本阶段只注册 `system.current_time`：

- 参数：可选 IANA 时区名称，默认系统本地时区。
- 结果：ISO 8601 时间和实际时区。
- 风险：`low`。
- 超时：2 秒。
- 副作用：无。

无效时区返回参数校验错误或稳定的 `invalid_timezone`，不回退到不明确的时间。

高风险路径使用测试注册表中的受控替身验证，不向生产注册表暴露假操作。

## 10. 错误与安全策略

- 未知工具：HTTP 404，错误码 `tool_not_found`。
- 参数非法：HTTP 422，不回显敏感原始值。
- 状态冲突：HTTP 409。
- 请求过期：返回 `expired` 状态，不执行。
- 工具异常：返回 `failed` 和稳定错误码。
- 数据库失败：停止请求，不尝试绕过持久化直接执行。
- WebSocket 通知失败：请求仍保存在 SQLite，Electron 可通过列表恢复。

所有错误响应都只包含安全文本、稳定代码和请求标识。

## 11. 测试策略

### 11.1 单元测试

- 工具注册和重复名称拒绝。
- 风险不能由请求参数覆盖。
- 参数脱敏、截断和深度限制。
- 低风险自动执行。
- 高风险未经批准不执行。
- 批准只执行一次。
- 拒绝、过期、取消和不可取消冲突。
- 执行超时和异常安全映射。

### 11.2 持久化测试

- 新数据库迁移到版本 2。
- 版本 1 数据库无损升级。
- 高风险请求与确认原子保存。
- 并发批准只有一个调用获得执行权。
- 审计顺序和脱敏内容正确。

### 11.3 集成测试

- 低风险时间查询通过 HTTP 自动完成。
- 测试高风险工具返回 `202`，批准后才执行。
- 拒绝和过期请求不执行。
- Electron 重连可读取待确认列表。
- WebSocket 能收到确认事件。

### 11.4 桌面契约测试

- renderer bundle 包含确认模块。
- 确认 DOM 使用按钮和状态区域。
- UI 只通过 `textContent` 渲染外部数据。
- API 调用路径与后端一致。

## 12. 验收标准

- 生产注册表只包含代码内明确注册的工具。
- `system.current_time` 无需确认即可执行并留下审计记录。
- 测试高风险工具在批准前执行次数始终为 0。
- 并发或重复批准不会重复执行。
- 拒绝、超时和取消路径都有持久化终态。
- 审计和确认 UI 不出现敏感原始参数。
- Electron 重连不会丢失待确认请求。
- 原有 152 个后端测试和 Live2D 桌面测试继续通过。
- 每个独立任务完成验证后创建 Git 提交。
