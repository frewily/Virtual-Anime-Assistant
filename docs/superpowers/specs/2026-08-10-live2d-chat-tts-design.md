# Live2D 模型回复自动朗读设计

## 1. 背景与目标

当前桌面端可以接收后端发布的 `speak` 消息，并播放消息中已有的 `audioUrl`。场景提醒会在后端提前合成音频，因此可以直接播放；普通模型聊天回复只有 `text`，不会触发 TTS，Live2D 在线时仍只有文字结果。

本阶段补齐桌面端自动朗读：Electron 收到没有 `audioUrl`、但包含非空 `text` 的 `speak` 消息后，通过现有 `POST /api/tts/speak` 接口合成并播放语音。

## 2. 范围

### 2.1 包含

- Live2D 桌面端自动朗读普通模型回复。
- 继续直接播放场景消息中已有的 `audioUrl`，不重复请求 TTS。
- 使用 `correlationId` 抑制同一条 WebSocket 消息的重复朗读。
- TTS 或浏览器音频播放失败时安全降级为无声，不影响聊天、动作或 WebSocket。
- 为音频直接播放、动态合成、空文本、失败降级和重复消息增加 Node.js 单元测试。

### 2.2 不包含

- 不修改 QQ 回复路径，QQ 消息不会触发桌面端朗读。
- 不修改模型网关、聊天接口或后端应用编排。
- 不增加语音开关、语音队列、打断策略、口型同步或音量控制。
- 不改变 GPT-SoVITS 与 EdgeTTS 的选择和回退规则。

## 3. 方案选择

采用桌面端按需合成方案。相比在后端同步合成，它只在 Live2D 实际在线并收到回复时产生 TTS 请求，不增加聊天 HTTP 接口延迟，也不会让 QQ 或纯 API 调用无意义地生成音频。

不采用完整异步语音任务队列，因为本阶段只需补齐单设备、本地桌面端的自动播放能力。

## 4. 组件边界

新增独立的语音播放模块，负责：

- 校验 `speak` 消息中的 `audioUrl`、`text` 与 `correlationId`。
- 直接播放已有音频。
- 在缺少音频时调用 TTS 接口，并校验返回的 `audio_url`。
- 维护有界的已处理 `correlationId` 集合。
- 捕获网络、响应解析和 `Audio.play()` 失败，只记录稳定错误类别。

WebSocket 模块仍只负责连接、消息分类和动作分发。其 `handleSpeak()` 将消息交给语音播放模块，并继续处理 `motion` 与 `expression`，避免把网络和媒体生命周期继续堆入 WebSocket 文件。

## 5. 数据流

### 5.1 已有音频

```text
后端场景提醒
  → WebSocket speak（包含 audioUrl）
  → 桌面端语音播放模块
  → Audio 播放
```

### 5.2 模型文字回复

```text
模型聊天回复
  → WebSocket speak（包含 text，不含 audioUrl）
  → POST /api/tts/speak
  → GPT-SoVITS 或 EdgeTTS 回退
  → 返回 audio_url
  → Audio 播放
```

请求体只包含：

```json
{
  "text": "模型回复正文"
}
```

桌面端不指定 `voice_id`，由后端使用 Web 设置中保存的默认音色。

## 6. 重复抑制与资源边界

- 存在非空 `correlationId` 时，在开始播放或请求 TTS 前登记该标识。
- 已登记的标识再次出现时直接忽略，不重复播放或合成。
- 集合最多保留最近 100 个标识；超出后移除最早记录，避免长期运行时无限增长。
- 缺少 `correlationId` 的兼容消息仍可播放，但不参与重复抑制。

## 7. 错误处理

- `audioUrl` 或 TTS 返回的 `audio_url` 必须是非空字符串，并通过固定后端地址 `http://127.0.0.1:8080` 解析。
- TTS 非 2xx、JSON 解析失败、字段缺失、网络异常和音频播放拒绝均不得向上抛出未处理异常。
- 日志只输出稳定类别，不记录回复正文、服务响应正文、地址参数或凭据。
- 失败只影响本次语音，不撤销已经显示的模型文字，不断开 WebSocket，也不阻止表情和动作处理。

## 8. 测试与验收

Node.js 单元测试使用注入的 `fetch`、`Audio` 和日志替身，覆盖：

1. 消息已有 `audioUrl` 时直接播放，且不调用 TTS。
2. 只有 `text` 时调用一次 `POST /api/tts/speak`，随后播放返回音频。
3. 空白 `text` 不请求 TTS。
4. TTS 非 2xx、畸形响应或播放失败时安全结束。
5. 相同 `correlationId` 不重复请求或播放。
6. 已处理标识集合保持 100 条上限。

完整验收包括：

- `npm test` 通过。
- Renderer 构建与主进程、preload 语法检查通过。
- Live2D 连接状态为在线。
- 真实模型回复返回 HTTP 200，并由桌面端调用 TTS 音频接口。
- TTS 失败时聊天回复仍然成功。

## 9. 已知限制

本阶段不处理多条回复同时播放造成的音频重叠，也不实现口型同步。它们需要独立的播放队列和模型参数驱动设计，不应混入本次最小闭环。
