# macOS 本机状态助手与受控操作设计

> 日期：2026-08-14
>
> 状态：已获用户批准
>
> 首版平台：macOS

## 1. 背景

Virtual Anime Assistant（以下简称 VAA）已经具备模型对话、SQLite 会话与记忆、
工具权限状态机、Electron 确认界面、Live2D、OneBot QQ 渠道和独立云端部署。
当前生产工具只有只读时间查询，助手不能感知本机状态，也不能执行有限的桌面操作。

本阶段不把 VAA 改造成 Claude Code 一类开发代理，也不提供任意 Shell。目标是让助手
通过代码内批准的 macOS 探针掌握电脑的实时状态，并在用户逐次确认后执行少量固定
操作。云端 QQ 只能查询由本机主动上报的脱敏状态，不能操作电脑。

参考项目 `Monika-Dream/live-dashboard` 提供了前台应用、空闲状态、电量、音乐和
隐私分级的实现思路。本设计只借鉴状态采集与隐私边界，不复制其公开仪表盘、活动
时间线或设备管理模式。

## 2. 目标

- 采集 macOS 当前状态，并向模型提供版本化、结构化、经过隐私过滤的快照。
- 状态仅保存在内存，不记录应用使用时间线。
- 桌面模型可以提出打开应用、打开 HTTPS 网页、播放暂停和音量调整请求。
- 所有操作必须经过 Live2D 确认卡片的「允许一次」，拒绝或超时不得执行。
- 云端 QQ 可以查询电脑是否在线及脱敏状态，但不能提出或执行电脑操作。
- 本机通过受限 SSH 隧道主动上报状态，不公开 8080、6099、3000 或 3001。
- 使用 Provider、Transport、Registry 和 Channel Policy 边界支持后续增加平台、
  设备、状态源和操作能力。
- 任一探针、传输或操作失败都不能影响聊天、QQ、Live2D 和其他 Provider。

## 3. 非目标

- 不执行模型生成的 Shell、AppleScript、Python、JavaScript 或其他代码。
- 不提供文件读写、软件安装、应用退出、锁屏、休眠、重启或关机。
- 不读取屏幕截图、剪贴板、键盘输入、浏览器 URL、文件内容或完整进程列表。
- 不保存历史活动、原始窗口标题、原始命令输出或远程操作队列。
- 不允许 QQ 绕过本机确认操作电脑，也不在首版提供 QQ 操作提议。
- 不修改宝塔、Nginx、防火墙、网站、博客、root 登录或密码登录配置。
- 不在首版支持 Windows、Linux、视觉模型或通用插件脚本。

## 4. 方案选择

### 4.1 选定方案：后端内置状态采集器

本机 FastAPI 运行固定 macOS 探针，将结果交给内存状态服务。工具注册表从状态服务
读取快照，并通过固定操作适配器执行用户批准的操作。首版沿用现有 Python 运行时，
避免新增一个需要安装、配置和保活的进程。

未来正式打包或支持多个平台时，可以把 Provider 移入独立本机 Agent；统一快照、
传输和能力注册接口保持不变。

### 4.2 未采用方案

**独立本机 Agent：** 隔离清晰，也最接近参考项目，但首版会增加安装、鉴权、保活、
升级和故障排查成本。

**Electron 主进程采集：** 桌面集成自然，但会让 Python 工具状态机跨越 HTTP、IPC
和 Electron 三层，确认恢复与测试边界更复杂。

**任意终端 Agent：** 能力最强，但远超“掌握状态并稍微操作”的需求，也会引入命令
注入、目录权限、秘密泄露和不可逆操作风险。

## 5. 总体架构

```text
固定 macOS 探针
    ↓
StateProvider 集合
    ↓
DesktopStateService ──→ 本机 computer.current_state ──→ 桌面模型
    │
    └──→ StateTransport ──受限 SSH 隧道──→ 云端最新快照
                                              ↓
                                 云端 computer.current_state
                                              ↓
                                            QQ 模型

桌面模型提出固定操作
    ↓
CapabilityRegistry + ChannelPolicy
    ↓
现有工具权限状态机
    ↓
Live2D「允许一次 / 拒绝」
    ↓
ActionProvider ──→ 固定参数数组或固定 AppleScript 模板
```

### 5.1 核心组件

- `StateProvider`：采集一个独立状态分区，不知道模型、QQ 或传输细节。
- `DesktopStateService`：并行调度 Provider、合并安全结果、缓存最新快照并计算过期。
- `ActionProvider`：实现一个固定操作，不接受原始命令文本。
- `StateTransport`：发送已过滤快照；首版实现本机内存和 SSH 隧道上报。
- `CapabilityRegistry`：保存能力名称、平台、风险、参数模型、Provider 和允许渠道。
- `ChannelPolicy`：根据运行模式、消息渠道、确认客户端状态和能力元数据生成可见目录。
- `RemoteDeviceStateStore`：云端按设备保存最新安全快照，不保存历史。

这些接口位于平台实现之上。macOS 命令、AppleScript 和进程细节只能出现在 macOS
Provider 中，不能泄漏到模型编排器、QQ 渠道或 API 路由。

## 6. 版本化状态模型

状态信封使用固定顶层字段：

```json
{
  "schemaVersion": 1,
  "deviceId": "macbook-main",
  "platform": "macos",
  "collectedAt": "2026-08-14T12:00:00Z",
  "expiresAt": "2026-08-14T12:00:45Z",
  "capabilities": [
    "system.resources",
    "system.presence",
    "application.foreground",
    "system.power",
    "system.network",
    "media.playback",
    "media.volume"
  ],
  "state": {}
}
```

规则如下：

- `schemaVersion` 为正整数。接收方拒绝不支持的未来主版本。
- `deviceId` 由本机配置生成，只允许小写字母、数字和连字符，长度不超过 64。
- `collectedAt` 使用 UTC；`expiresAt` 首版固定为采集后 45 秒。
- `capabilities` 只包含本次快照实际提供的能力。
- `state` 按 capability 命名空间组织；新增字段必须可选。
- 旧接收方忽略已知主版本中的未知字段，不因扩展字段拒绝整份快照。
- 单个分区失败时记录安全的 `status: unavailable` 和稳定错误码，不包含异常文本。

### 6.1 首版状态分区

`system.resources`：CPU、内存和系统磁盘使用率。

`system.presence`：`active`、`idle` 或 `locked`，以及按整分钟向下取整的空闲时间。

`application.foreground`：隐私处理后的应用名、分类和是否全屏。窗口标题只有在隐私
策略明确允许时才出现，最长 128 个字符。

`system.power`：电池百分比、是否充电；无电池设备返回 `not_applicable`。

`system.network`：是否存在可用默认网络，不扫描局域网，不探测外部网站。

`media.playback`：已知播放器的 `playing`、`paused` 或 `unavailable`，以及允许公开的
歌曲名和歌手。

`media.volume`：`0～100` 的输出音量和静音状态。

## 7. macOS Provider

首版 Provider 使用代码内固定的系统接口：

- 系统资源与电池优先使用 `psutil`。
- 前台应用、全屏、锁屏、播放器和音量使用固定 AppleScript 模板。
- 空闲时间使用固定参数调用 `ioreg`。
- 音频活动和电源断言使用固定参数调用 `pmset`。
- 网络状态使用固定参数调用 `scutil` 或等价系统 API。

执行规则：

- Python 子进程必须使用参数数组和异步 `exec` 接口，不得使用 `shell=True`。
- Provider 不接受来自模型、API、配置文件或状态数据的命令、参数或脚本片段。
- 单个探针超时为 3 秒；超时后终止子进程并返回稳定错误码。
- 采集任务在线程或异步子进程中执行，不阻塞 FastAPI 事件循环。
- 原始输出只存在于当前解析调用，生成结构化分区后立即释放。
- 状态服务每 5 秒采集一次；变化会立即更新缓存，远端上报至少每 15 秒发送一次。

## 8. 隐私分级

前台应用在本机完成分级，远端和模型不能要求降低级别：

- `SHOW`：允许应用名和经过长度限制的窗口标题。
- `BROWSER`：只显示浏览器名称，不显示页面标题或 URL。
- `HIDE_TITLE`：显示应用名，但隐藏窗口标题。
- `SECRET`：应用名统一替换为「私密应用」，不返回标题或细分类别。

保守默认规则：

- 浏览器使用 `BROWSER`。
- 聊天、邮件、终端、开发终端和系统工具使用 `HIDE_TITLE`。
- 银行、券商、密码管理器、验证器和政务应用使用 `SECRET`。
- 未识别应用默认使用 `HIDE_TITLE`，不能因映射缺失公开标题。
- 音乐元数据只对已知播放器公开；未知音频活动只返回“正在播放音频”。

隐私分类表由代码内静态数据提供。未来允许本地配置覆盖时，只能维持或提高默认隐私
等级；降低 `SECRET` 或 `HIDE_TITLE` 必须通过独立的显式本机授权设计。

不得在日志、SQLite、审计详情、WebSocket 事件或异常文本中记录原始窗口标题、歌曲
信息、URL 或探针输出。工具审计只记录能力名称、设备标识和安全状态摘要。

## 9. 本地与云端状态

### 9.1 本地内存状态

`DesktopStateService` 只保存最新安全快照。进程退出后状态自然消失，不写入 SQLite。
最新快照超过 15 秒没有刷新时，本地工具返回 `stale`，并指出不可用分区。

### 9.2 QQ 只读状态同步

Mac 使用一把独立的状态上报 SSH 密钥建立到服务器回环接口的本地端口转发。该密钥
只能转发到服务器 `127.0.0.1:8080`，不能获得 Shell、PTY、Agent Forwarding、X11
Forwarding 或其他端口访问。

上报流程：

1. 本机完成全部采集和隐私过滤。
2. 隧道客户端使用 `BatchMode=yes`、`IdentitiesOnly=yes` 和
   `StrictHostKeyChecking=yes`，known hosts 必须预先核对。
3. 本机通过隧道向云端回环 API 提交版本化状态信封。
4. API 使用独立的每设备 Bearer Token 鉴权，并校验设备标识、时间窗口、版本和大小。
5. 云端只替换该设备的最新快照；比当前快照更旧或相同的 `collectedAt` 被拒绝。
6. 上报成功或失败均不记录状态正文；失败采用有上限的指数退避。

每份快照最大 32 KiB。正常情况下每 15 秒上报一次；超过 45 秒没有新快照时，云端
工具把设备标记为离线。云端重启后状态为空，等待下一次心跳恢复。

状态 API 继续只监听回环地址。首版不修改 Nginx、网站、博客或防火墙，也不公开任何
新的管理端口。SSH 密钥和上报 Token 不进入 Git、Web 设置响应、聊天或日志。

### 9.3 多设备扩展

云端存储接口从首版开始以 `deviceId` 为键。首版只配置一个默认设备；未来增加设备
时无需修改状态模型和 QQ 工具，只需新增独立凭证与设备选择参数。

## 10. 能力注册与渠道策略

每个能力定义至少包含：

- 稳定名称和标题。
- 所需平台与运行模式。
- 参数模型和结果模型。
- 风险等级与影响说明。
- Provider 或 ActionProvider。
- 可见渠道与模型访问模式。
- 超时、取消和敏感字段声明。

模型访问模式为：

- `hidden`：模型不可见。
- `read_only`：低风险能力可以自动执行。
- `propose_with_confirmation`：模型只能提出请求，批准前不能执行。

首版渠道矩阵：

| 能力 | 本地 Desktop | 云端 QQ | System |
| --- | --- | --- | --- |
| `computer.current_state` | 只读 | 只读远端快照 | 只读 |
| `computer.open_application` | 提议并确认 | 隐藏 | 隐藏 |
| `computer.open_url` | 提议并确认 | 隐藏 | 隐藏 |
| `computer.toggle_media` | 提议并确认 | 隐藏 | 隐藏 |
| `computer.set_volume` | 提议并确认 | 隐藏 | 隐藏 |

`computer.current_state` 在本机运行时读取 `DesktopStateService`，在云端运行时读取
`RemoteDeviceStateStore`。两个实现返回同一结果模型，模型和渠道不需要判断数据来源。

模型工具目录必须接收原始消息渠道，不能继续对 Desktop 和 QQ 返回同一静态目录。
工具请求持久化原始消息渠道，执行服务在目录过滤后再次校验渠道、平台、运行模式、
风险和确认客户端在线状态。模型不能覆盖这些字段。

## 11. 受控操作

### 11.1 参数边界

`computer.open_application` 接受应用显示名或 Bundle ID，长度不超过 100。值不得包含
路径分隔符、控制字符、换行或命令选项。适配器使用固定的 `/usr/bin/open` 参数数组；
应用已运行时由 macOS 聚焦现有实例。

`computer.open_url` 只接受最长 2048 字符的绝对 HTTPS URL。禁止用户名、密码、片段
中的控制字符、IP 字面量、`localhost`、`.local` 和非 HTTPS 协议。URL 在工具定义中
声明为敏感字段，审计不保存原值。确认卡片显示规范化主机名和路径；查询参数只显示
参数名，参数值统一替换为 `[已隐藏]`。

`computer.toggle_media` 只接受当前已识别且代码内支持的播放器标识。每个播放器使用
独立固定 AppleScript 模板，不拼接模型文本。

`computer.set_volume` 只接受整数 `0～100`，使用固定 AppleScript 模板。

### 11.2 模型提议与恢复

现有模型编排器只允许低风险工具。本阶段增加显式的“可提议高风险能力”，但不能把
高风险能力降级为低风险：

1. 只有原始渠道为 Desktop、运行在本机 macOS、Electron 确认连接在线，且能力声明
   `propose_with_confirmation` 时，操作工具才进入模型目录。
2. 模型工具调用创建高风险请求和确认记录，不执行 ActionProvider。
3. 当前聊天回合在内存中等待确认，最长 60 秒。WebSocket 可在聊天 HTTP 请求等待时
   独立发送确认卡片。
4. 批准后现有原子认领逻辑保证只执行一次；结果作为工具结果交回模型，再生成最终
   回复。
5. 拒绝、过期、取消、Electron 断线或服务重启时请求进入安全终态，ActionProvider
   执行次数保持为 0。

待确认参数继续只保存在当前进程内，不为恢复能力把操作参数持久化。服务重启后不补
执行旧请求。QQ 永远不会获得这些工具定义，也不能创建对应确认。

## 12. 配置与用户同意

本机状态采集、桌面操作和远端状态上报使用 3 个独立开关，默认全部关闭：

- 本机状态采集。
- 本机受控操作。
- 向云端上报脱敏状态。

启用状态采集前，设置页说明采集字段、不会采集的内容和 macOS 权限要求。启用远端
上报前，设置页再次说明 QQ 可见范围。关闭任一开关立即停止对应后台任务；关闭远端
上报后云端快照按 45 秒 TTL 自动离线。

SSH 私钥、known hosts 和设备 Token 只能由本地环境或权限为 `0600` 的秘密文件提供。
设置 API 只返回“已配置”状态，不返回秘密值。

## 13. 错误语义

| 场景 | 稳定结果 |
| --- | --- |
| macOS 辅助功能权限缺失 | `permission_required` |
| Provider 超时 | `state_probe_timeout` |
| 单个状态分区不可用 | 分区 `status: unavailable` |
| 本地快照过期 | `state_stale` |
| 云端快照过期 | `device_offline` |
| 不支持的平台或运行模式 | `capability_unavailable` |
| 渠道不允许该能力 | 对模型隐藏；直接请求返回 `tool_not_found` |
| Electron 确认连接离线 | `confirmation_client_unavailable` |
| 操作参数非法 | `tool_arguments_invalid` |
| 应用不存在 | `application_not_found` |
| URL 被策略拒绝 | `url_not_allowed` |
| 播放器不可用 | `media_player_unavailable` |
| 操作超时 | `execution_timeout` |
| SSH 隧道或上报失败 | 本机状态继续工作，按上限退避重试 |

错误正文不得包含原始命令输出、窗口标题、URL 查询参数、文件路径、密钥或异常堆栈。

## 14. 测试策略

### 14.1 Provider 单元测试

- 使用替身进程执行器验证固定可执行文件、参数数组和 3 秒超时。
- 静态扫描禁止 `shell=True`、`shell=True` 的等价封装和动态脚本拼接。
- 覆盖资源、前台应用、空闲、锁屏、电池、网络、播放器和音量解析。
- 单个 Provider 失败时其他分区仍生成，异常正文不进入结果。

### 14.2 隐私测试

- 浏览器隐藏页面标题和 URL。
- 聊天、邮件和终端隐藏标题。
- 银行、密码管理器和验证器统一为「私密应用」。
- 未识别应用默认隐藏标题。
- 日志、SQLite、审计和 API 不包含原始敏感值。

### 14.3 状态与传输测试

- 快照版本、大小、设备标识、UTC 时间和 TTL 校验。
- 最新快照替换、旧快照拒绝、45 秒离线和云端重启空状态。
- Token 缺失或错误时拒绝上报，不回显凭证。
- 隧道失败不影响本地状态，退避有上限且可停止。
- 云端契约继续保证管理端口只绑定回环地址。

### 14.4 工具与渠道测试

- Desktop、QQ 和 System 获得精确的能力目录。
- QQ 和云端无法发现或请求操作能力。
- 高风险模型提议未经确认不执行。
- 批准只执行一次，结果返回模型后才允许声称成功。
- 拒绝、过期、取消、断线和重启均不执行。
- URL、应用、播放器和音量参数边界不可绕过。

### 14.5 回归测试

- 后端完整测试无失败。
- 桌面端完整测试和 Renderer 构建无失败。
- 云端部署契约、监控、备份和 Git bundle 自动部署无回归。
- Tool Calling 关闭或电脑能力关闭时，现有桌面与 QQ 行为保持不变。

## 15. 人工验收

1. 首次启用时能看到清晰的隐私与权限说明。
2. 桌面询问“我的电脑现在是什么状态”，助手依据真实脱敏快照回答。
3. 浏览器、终端和敏感应用前台时，API、日志和模型上下文不出现原始标题。
4. 要求打开应用、HTTPS 网页、播放暂停或调节音量时，批准前没有任何动作。
5. 批准后只执行一次，模型依据真实结果回复；拒绝和超时不执行。
6. QQ 可以查询电脑在线、使用状态、电量、负载、网络、音乐和音量。
7. QQ 请求操作电脑时，模型明确说明该渠道没有操作权限。
8. Mac 断网、休眠或关闭上报后，QQ 在 45 秒内显示电脑离线。
9. 8080 和 6099 仍只绑定回环地址，3000 和 3001 未监听。
10. 网站、博客、NapCat 登录、云端备份和监控不受影响。

## 16. 扩展约束

新增能力的标准流程为：实现 Provider、注册能力、声明渠道与风险、增加测试。核心采集
循环、传输协议、模型编排和 QQ 适配器不因单个能力改变。

未来扩展遵循以下规则：

- Windows 和 Linux 通过平台 Provider 接入，不复用 macOS 命令。
- 多设备继续使用同一版本化信封和按设备最新快照存储。
- 日历、提醒、通知和视觉感知使用独立 capability 命名空间。
- 新操作继续复用参数模型、确认、审计、超时和 Channel Policy。
- 外部插件只能注册声明式能力，不能注入任意命令或绕过本地风险定义。
- 主版本升级必须提供显式兼容策略；不能静默改变既有字段语义。
- 安全默认值保持“未配置即关闭、未知即隐藏、失败即不执行”。

该边界保证功能扩展集中在独立 Provider 和注册信息中，同时保留现有工具权限状态机
作为唯一执行入口。
